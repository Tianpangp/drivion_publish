# 执行系统接入指南

## 1. 接入目标

Exe Runtime 完成以下流程即算完成 Publish 适配：

1. 用发布系统中的 `equipment_id` 查询当前绑定。
2. 发现 `revision` 变化后，下载该设备绑定的 AutoUnit 精确版本。
3. 校验 SHA-256，解压到新的本地版本目录。
4. 从 AutoUnit 元数据读取 HAL 依赖，逐个按 `name + version` 解析和下载。
5. 全部制品校验成功后原子切换本地当前版本；失败时继续使用上一个本地完整版本。

Exe DevKit 可通过同一组对外 API 提交构建好的 AutoUnit 或 HAL 包。提交成功不代表发布成功，新制品始终从 `pending_testing` 开始。

## 2. 基础地址与请求头

本地默认地址：

```text
http://localhost:8001/publish/api/v1/exe
```

所有对外接口都需要 Bearer 凭据：

```http
Authorization: Bearer <credential>
Accept: application/json
```

上传使用 `multipart/form-data`，文件字段名固定为 `file`。下载接口返回原始二进制数据，不包在 JSON `data` 中。

## 3. 鉴权

### 3.1 Publish 使用内置认证

Publish `config.toml` 配置：

```toml
[auth]
mode = "local"

[integration]
api_key_env = "PUBLISH_INTEGRATION_API_KEY"
```

在 Publish 后端运行环境中设置一个随机值：

```bash
export PUBLISH_INTEGRATION_API_KEY="$(openssl rand -hex 32)"
```

Exe/DevKit 用同一值作为 Bearer 凭据。该 Key 只用于机器间接口，不是用户登录 Token，不应写入代码或提交到 Git。

### 3.2 Publish 使用 Drivion SSO

Exe Runtime 建议使用 SSO Client Credentials。该客户端签发的 Token audience 必须是 Publish 校验的 `release`：

```toml
[oidc.clients.execution_publish]
name = "Exe 访问 Publish"
public = false
service_only = true
client_secret_env = "EXECUTION_PUBLISH_OIDC_SECRET"
audience = "release"
allowed_scopes = ["release.read", "release.write"]
service_roles = ["service.account"]
service_permissions = [
  "platform.equipment.read",
  "artifact.package.read",
  "artifact.package.download",
]
permission_grants = [
  { permission = "platform.equipment.read", scopeType = "line", scopeId = "line-a" },
  { permission = "artifact.package.read", scopeType = "line", scopeId = "line-a" },
  { permission = "artifact.package.download", scopeType = "line", scopeId = "line-a" },
]
```

获取 Token：

```bash
curl -u "execution_publish:${EXECUTION_PUBLISH_OIDC_SECRET}" \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  -d 'grant_type=client_credentials&scope=release.read' \
  http://localhost:8002/api/auth/oauth/token
```

Publish 会验证 Token 的 RS256 签名、Issuer、Audience、过期时间、`token_use=access`、Permission 和资源 Scope。

拉取设备数据时，以下 scope 任一匹配即可：

- `equipment/<equipmentId>`
- 设备所属 `station/<stationId>`
- 设备所属 `line/<lineId>`
- 设备所属 `site/<siteId>`
- `tenant/*`

不能用 OAuth Scope 代替 Permission 和资源 Scope。

DevKit 提交制品需要 `autounit.definition.publish` 或 `hal.driver.publish`。与 Publish 管理端的现有规则一致，制品提交只检查 Permission，不用 scope 限制厂区/线体，并会在提交前做 introspection。

## 4. Runtime 拉取流程

### 4.1 查询当前绑定

```http
GET /publish/api/v1/exe/equipment/{equipmentId}/deployment
```

关键响应：

```json
{
  "code": 200,
  "message": "获取成功",
  "data": {
    "equipment": {
      "id": "equipment-001",
      "name": "上料机",
      "code": "EQ-001",
      "status": "active",
      "station": {"id": "station-001", "name": "上料工位", "code": "ST-001"},
      "line": {"id": "line-a", "name": "A 线", "code": "LINE-A"},
      "site": {"id": "site-1", "name": "一厂", "code": "SITE-1"}
    },
    "autoUnit": {
      "id": "au-version-id",
      "name": "上料自动化逻辑",
      "packageId": "feeding.logic",
      "version": "1.4.2",
      "module": "feeding_logic",
      "status": "published",
      "published": true,
      "releaseWarning": null,
      "size": 43120,
      "md5": "...",
      "sha256": "...",
      "downloadApiPath": "/publish/api/v1/exe/equipment/equipment-001/autounit/download",
      "metadata": {"dependencies": []}
    },
    "boundAt": "2026-07-15 09:30:00",
    "revision": "9e40...",
    "generatedAt": "2026-07-15T01:30:10+00:00"
  }
}
```

`autoUnit = null` 表示设备当前未绑定 AutoUnit，不是错误。`revision` 是不透明变更标识；Exe 只比较是否改变，不解析其内容。

发布系统允许设备绑定未发布 AutoUnit。此时 `published=false` 且 `releaseWarning` 非空。Exe 必须保留该状态给本地部署策略，不得自动改拉同名已发布版本。

### 4.2 下载 AutoUnit

使用服务端返回的 `downloadApiPath`：

```http
GET /publish/api/v1/exe/equipment/{equipmentId}/autounit/download
```

下载后必须按元数据中的 `size` 和 `sha256` 校验。响应头也提供 `ETag`、`X-Artifact-SHA256` 和 `X-Artifact-MD5`。

### 4.3 解析和下载 HAL

```http
GET /publish/api/v1/exe/equipment/{equipmentId}/hal?name=demo-hal&version=1.0.0
GET /publish/api/v1/exe/equipment/{equipmentId}/hal/download?name=demo-hal&version=1.0.0
```

HAL 必须使用 AutoUnit 声明的精确版本。Publish 不提供“最新版本”自动解析。

## 5. DevKit 提交流程

### 5.1 首次提交

```bash
curl -X POST \
  -H "Authorization: Bearer ${PUBLISH_CREDENTIAL}" \
  -F "file=@dist/my-autounit-1.0.0.zip" \
  http://localhost:8001/publish/api/v1/exe/artifacts/autounit
```

HAL 使用 `/artifacts/hal`。名称、版本和入口不从表单提交，Publish 只信任压缩包内的元数据。成功响应的 `data.id` 是该版本的 `artifact_id`。

### 5.2 更新待测试版本

```http
PUT /publish/api/v1/exe/artifacts/autounit/{artifactId}
PUT /publish/api/v1/exe/artifacts/hal/{artifactId}
Content-Type: multipart/form-data; boundary=...
```

只有 `pending_testing` 版本可更新，且新包解析出的身份必须和原版本一致：

- AutoUnit：`package_id + version` 不得变化。
- HAL：`project.name + project.version` 不得变化。

更新会取消尚未完成的测试审批。版本进入测试后被锁定，必须退回 `pending_testing` 后才能再次更新。

### 5.3 提交的非幂等性

`POST` 上传不是幂等操作。相同身份版本已存在时返回 `409`，不自动覆盖。客户端只能在明确拿到 `artifact_id` 后调用 `PUT`。

## 6. 状态处理

| 状态 | 含义 | Exe 建议 |
| --- | --- | --- |
| `pending_testing` | 待测试，可更新或删除 | 仅测试设备按本地策略使用 |
| `testing` | 测试审批已通过，版本已锁定 | 仅测试设备按本地策略使用 |
| `pending_publish` | 等待发布审批 | 不应视为已发布 |
| `published` | 已发布 | 生产设备正常使用 |
| `pending_remove` | 等待下架审批 | 保留当前本地完整版本 |
| `removed` | 已下架，禁止新的拉取 | 不安装，等待新绑定 |

Publish 不会远程删除 Exe 已安装的本地文件。Exe 自己负责本地版本保留、激活和回滚策略。

## 7. 轮询、缓存与故障处理

- 启动时查询 deployment，运行期可低频轮询；Publish 当前不推送变更。
- `revision` 未变时不重复下载。
- 下载到临时文件，校验大小和 SHA-256 后再改名/切换。
- `401` 时重新取得凭据；`403` 是权限或 scope 问题，不高频重试。
- `404/409` 是发布数据或精确版本问题，需要人工处理。
- `5xx` 可指数退避重试。Publish 短暂不可用不应导致 Runtime 停止当前已安装版本。

## 8. Python 对接起点

[`examples/publish_client.py`](./examples/publish_client.py) 已实现 deployment 查询、AutoUnit/HAL 流式下载与 SHA-256 校验，以及制品首次提交/更新。Exe 还需要接入自己的本地包仓、原子激活和回滚逻辑。
